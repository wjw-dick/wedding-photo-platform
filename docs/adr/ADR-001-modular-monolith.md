# ADR-001：模块化单体 + 一后端多前端壳

- 状态：已接受
- 日期：2026-11
- 决策人：技术负责人、架构评审

## 背景

平台有 9 个前端入口（平台端、租户后台、官网、公众号、4 个小程序、H5、App），峰值 300 QPS，单团队维护，租户规模预期 ≤ 50。订单、档期、生产、选片、制作、交付高度耦合，跨端共享会员、订单、权限、存储与审计。

## 决策

后端采用 Spring Boot 3 模块化单体，按业务域分包（`platform`、`tenant`、`biz/*`、`open`、`job`），每个域只暴露 Service 接口；所有端共用一套 API、JWT 认证、RBAC、UnionID 会员、租户上下文与对象存储。前端只做壳与角色差异。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A 模块化单体（采用） | 事务一致、部署简单、联调成本低、团队匹配 | 需约束模块腐化；单进程故障域大 | 采用 |
| B 微服务拆分 | 独立扩容、团队并行 | 分布式事务、链路追踪、9 端主数据同步复杂，运维成本高 | 不采用 |
| C 每端独立后端 | 单端迭代自由 | 会员与订单分裂，违背 UnionID 互通 | 不采用 |

## 后果

- 正面：下单-锁档-生产-交付在同一事务边界内；一套权限与审计；部署只需一个应用镜像。
- 负面：模块边界依赖代码评审与包可见性约束；应用层扩容是主要手段。
- 缓解：领域分包 + Service 接口 + 禁止跨域 Mapper；压测后按无状态水平扩容；后续若单域负载突出，可按 `biz/*` 边界拆出。
