# ADR-003：对象存储抽象与客片签名访问

- 状态：已接受
- 日期：2026-11
- 决策人：技术负责人、客户 IT、安全评审

## 背景

客片是核心资产（单租户 8 TB、60 万文件），不同客户对存储有不同偏好（自建 MinIO、阿里云 OSS、腾讯云 COS、AWS S3、本地磁盘）。客片含肖像隐私，必须私有访问、可审计、可追溯，且驱动切换不能导致历史文件不可读。

## 决策

定义统一 `StorageProvider` 接口，实现 5 种驱动：LOCAL、MINIO、OSS、COS、S3。后台可视化配置 Endpoint/Bucket/Region/AK/SK，连接测试通过后才允许保存；密钥 AES 加密，页面仅掩码，留空表示不修改。路径固定：

```
tenants/{tenantId}/orders/{orderNo}/{raw|retouched|print}/{fileName}
```

私有桶 + 签名 URL（有效期 ≤ 30 分钟）；后台预览叠加订单号与员工工号水印；批量下载二次确认并写审计；按月对账文件数与容量。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A 抽象驱动 + 5 实现（采用） | 客户可选、迁移灵活、本地可离线 | 需统一能力差异（签名、分片、版本） | 采用 |
| B 只用云 OSS | 省运维、CDN 成熟 | 中小客户流量成本高，数据出境合规复杂 | 不采用 |
| C 全部本地磁盘 | 成本最低、数据自主 | 无版本保护、扩容与异地备份困难 | 仅作开发/最小部署驱动 |

## 后果

- 正面：同一套上传/下载/签名逻辑适配 5 驱动；切换驱动有二次确认；历史文件按记录的原驱动读取。
- 负面：不同驱动能力不完全一致（如本地磁盘无原生签名），需在 Provider 内做等价实现。
- 缓解：连接测试作为保存前置；上传失败回滚数据库记录，避免半截文件；版本保护与回收站由部署层开启；月度对账任务发现缺失即告警。
